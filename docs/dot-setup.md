# Dot、定时运行与主动提醒

技能解决“每次应该怎样工作”，保存的定时任务解决“什么时候工作”，聊天或 Dot 解决“把结果送到哪里”。这三项需要分别配置和验证。

Dot 是可选项。建议先使用本机 Codex 的定时任务；Dot 显示 No access 时，仍可以使用本机方案。只有希望 Dot 协调该职责时才需要另行连接电脑。

## 直接使用当前聊天的定时任务

在能够访问本项目的 Codex / ChatGPT 桌面聊天里，先手动运行一轮技能，检查来源和输出。根据官方[定时任务文档](https://learn.chatgpt.com/docs/automations?surface=app)，本地任务需要电脑开机、桌面应用运行；可以在现有聊天保存定时任务，持续使用该聊天的上下文。随后让应用保存例行任务，明确：

- 使用哪个技能、项目和信息来源。
- 时间、时区、工作日以及是否有结束日期。
- 每轮要交付的简报内容。
- 返回当前聊天还是由另一个已确认入口交付。

可直接对应用说：

> 在我的本地时区，每个工作日使用$personal-assistant，依据当天相关Codex工作和可用来源核实重点。09:00、14:00、18:00只在我的飞书AI助理对话发1–3条编号提醒，约80–160汉字，无变化只1条下一步，不保存白天文档。21:00只保存一份“YYYY-MM-DD 工作总结”：成果≤3、问题≤2（无则省）、明日计划≤3，约250–400字，内容少可更短。不放方法、源码路径、证据ID、表格或长学习清单，不自动更新项目/目标/学习/导航。保留当前聊天简洁兜底，请保存并确认日程、时区和投递位置。

上述21:00适合工作到21:00的用户，实际时间按个人工作窗口调整。白天只用`plan --preview`的stdout JSON或内部推理排程，不生成MD/ICS；普通plan仅用于用户另要的日历草案。到Scheduled检查是否已保存；对话中说一次时间或安装技能都不能证明任务已存在。修改时先找现有任务，不重复创建同一职责。

固定简报每轮都交付，“无变化不打扰”只用于额外轮询。21:00没有足够成果证据时如实说明，不虚报或推断全天无工作；影响决策的缺口只末尾一句。线程结束、助手自检和自动简报不能冒充研发交付。周报仅用户要求时约400–600字，成果/风险/下周各≤3项，不新增定时或周报文件；当晚生成则合并当晚唯一总结。技术细节放适用的现有需求/技术文档，另行明确的研发文档请求正常处理。

## 交给 Dot 协调

根据官方 [Getting started](https://learn.chatgpt.com/docs/dots/getting-started) 和 [Computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps)：

1. 先创建 Dot，在桌面应用的 Dot 资料页连接所需电脑。连接由电脑所有者确认，本仓库不会代替用户操作授权界面。
2. 保持该电脑在线并运行桌面应用。Dot 可以协调云端工作，但本项目的本地文件、SQLite 与飞书 CLI 只能在连接的电脑可用时访问。
3. 给 Dot 指明项目位置和工作职责。让它读取该目录的 `AGENTS.md`、本地配置与已安装技能，核实可用信息来源。
4. 明确时间、时区和投递位置，让 Dot 确认实际保存的任务，并检查 Scheduled。

首次交接可以说：

> 请承担我的持续工作助理职责，在连接的电脑上使用这个项目和 personal-assistant 技能。沿用已设置的例行任务与本人飞书投递目标：白天只编号提醒，日终只保存一份精简总结，不自动更新其他云文件。Dot对话仅在我选择它作为投递目标时使用，避免与原聊天重复提醒。先核验电脑、项目、已有日程及目的地，再说明哪些实际接通；没有日程时再确认需要的时间和时区。

“这个项目目录”应替换或附上自己真实的本机目录。不要把其他人的用户名或绝对路径复制到自己的配置里。

Dot 可以继续已有本地 Codex 工作，但连接电脑不会自动让每个历史聊天、所有应用或所有本地文件都成为当前上下文。请明确指出这项助理职责和项目；参见官方 [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory)。

## 验证送达与通知

需要分别确认：

| 检查 | 成功依据 |
| --- | --- |
| 电脑连接 | Dot 资料页的电脑条目显示已连接，且能实际读取被授权的项目文件 |
| 信息来源 | 实际用户身份查询成功；已安装 CLI 或 Bot ready 都不够 |
| 定时任务 | Scheduled 中存在正确的时间、时区、职责和目标 |
| 消息送达 | 一次真实运行的简报出现在预期聊天，而非只生成文件 |
| 系统通知 | 应用与操作系统通知权限开启，实际提醒可见 |

官方 [Notifications](https://learn.chatgpt.com/docs/notifications) 说明桌面提示有单独设置，操作系统也可能要求通知权限。启用任务不保证一定弹窗；不要用“自动化创建成功”代替送达验证。可在应用支持的界面手动触发一次运行，并检查结果与任务状态。

## 审批等待和中断

飞书企业审批未通过时，继续邮箱及本地待办，明确一次来源缺口，不反复发起授权。电脑离线、授权失效或接口读取失败时，不把缺失数据说成“没有事项”。

暂停一次工作和取消未来日程是不同操作。更换投递入口时先核对旧日程，再更新或停用旧任务，避免当前聊天和 Dot 对同一份简报各发一次。本仓库不会自行迁移、删除或创建 Dot 账户。
